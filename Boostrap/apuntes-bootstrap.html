Bootstrap 5.3 — manual de uso y ejemplos explicados

Apuntes para aprender a maquetar páginas web con Bootstrap: qué es, cómo se instala, el sistema de rejilla, el diseño responsive, los componentes más usados, cómo personalizarlo y, con especial detalle, los formularios y su validación.

Cómo leer estos apuntes
  • Este archivo usa el propio Bootstrap (cargado desde CDN), así que todos los ejemplos son reales y funcionan: puedes pulsar botones, abrir modales y probar los formularios. Necesitas conexión a Internet al abrirlo.
  • Cada ejemplo tiene tres partes: el resultado, el código (se puede plegar y copiar) y la explicación de cómo y por qué.
  • Cambia el ancho de la ventana para ver el comportamiento responsive. Arriba a la derecha tienes un indicador del breakpoint activo y un botón de modo oscuro.
  • Versión de referencia: Bootstrap 5.3.8 (la última estable de la rama 5).

1. ¿Qué es Bootstrap?

Bootstrap es un framework front-end de código abierto (licencia MIT) para crear sitios web responsive y mobile first. Nació en Twitter en 2011 (Mark Otto y Jacob Thornton) y hoy es uno de los frameworks CSS más usados del mundo.

En la práctica es un conjunto de tres cosas:

Un archivo CSS

Con un sistema de rejilla, estilos base (reboot), tipografía, componentes y cientos de clases de utilidad (mt-3, d-flex, text-center…).

Un archivo JavaScript

Da vida a los componentes interactivos: modales, desplegables, menús colapsables, tooltips, carruseles, toasts… Ya no necesita jQuery desde la versión 5.

Código fuente Sass

Variables, mapas y mixins para generar tu propia versión de Bootstrap con tus colores, fuentes y solo los componentes que uses.

¿Por qué usarlo?

  • Rapidez: maquetas en minutos lo que a mano llevaría horas.
  • Responsive de serie: la rejilla y las utilidades se adaptan a móvil, tablet y escritorio.
  • Consistencia: todo el equipo usa las mismas clases y el diseño queda homogéneo.
  • Compatibilidad y accesibilidad: probado en los navegadores modernos y con atributos ARIA en sus componentes.
  • Ecosistema enorme: plantillas, temas, iconos, documentación y comunidad.

Inconvenientes a tener en cuenta

  • Las webs pueden parecerse mucho entre sí si no se personaliza.
  • Si cargas el CSS completo y usas poco, estás enviando código que no necesitas (se soluciona compilando con Sass solo lo que usas).
  • El HTML se llena de clases; hay que conocer la nomenclatura.

2.1 Plantilla básica con CDN (la forma más rápida)

Este es el esqueleto mínimo de cualquier página con Bootstrap. Cópialo como punto de partida:

¿Por qué este orden?
  • meta viewport: sin ella, el móvil "finge" ser una pantalla de ~980px y reduce la página: los breakpoints nunca se activan.
  • CSS propio después del de Bootstrap: en CSS, a igual especificidad gana la última regla. Así tus estilos pueden sobrescribir los suyos sin usar !important.
  • JS al final del body (o con defer): el HTML se pinta antes y los scripts encuentran los elementos ya creados.
  • bootstrap.bundle.min.js vs bootstrap.min.js: el bundle incluye Popper. Si usas el otro, tienes que cargar Popper por separado antes.

2.4 ¿Cómo se usa? La idea clave

Bootstrap funciona añadiendo clases al HTML. No escribes CSS para cada cosa: combinas clases ya preparadas. Las clases siguen patrones fáciles de recordar:

  • Componente: btn, card, alert, navbar…
  • Modificador (variante): btn-primary, alert-danger, btn-lg…
  • Utilidad (una sola propiedad CSS): mt-3 (margin-top), text-center, d-none…
  • Infijo responsive: col-md-6, d-lg-block, text-sm-end → "a partir de este tamaño".
  • Atributos data-bs-*: activan el JavaScript sin escribir código: data-bs-toggle="modal", data-bs-target="#id".

3. Containers y sistema de columnas (grid)

La rejilla es el corazón de Bootstrap. Se basa en tres piezas que siempre van anidadas en este orden: container → row → col.

3.1 Breakpoints (puntos de ruptura)

3.2 Containers

El container centra el contenido y le da márgenes laterales (padding). Hay tres tipos:

  • .container: ancho fijo que "salta" en cada breakpoint (ver tabla). El más usado para el contenido.
  • .container-fluid: siempre al 100% del ancho. Ideal para cabeceras, paneles de administración o secciones a sangre.
  • .container-{bp} (ej. .container-md): 100% hasta ese breakpoint y fijo a partir de él.
Ejemplo 1 · Tipos de container
.container (ancho fijo por breakpoint)
.container-md (fluido hasta md, después fijo)
.container-fluid (siempre 100%)

Cómo: basta con envolver el contenido en un div con la clase. Por qué: sin container, el contenido iría pegado a los bordes y las .row (que tienen márgenes negativos) provocarían scroll horizontal. Dentro de esta página los anchos se ven reducidos porque el ejemplo está dentro de otra columna.

3.3 Filas y columnas

La fila se divide en 12 partes. Una columna .col-4 ocupa 4/12 (un tercio), .col-6 la mitad, etc. Si no indicas número (.col), las columnas se reparten el espacio a partes iguales.

Reglas de oro:

  1. Las columnas siempre son hijas directas de una .row, y el contenido va dentro de las columnas.
  2. Si las columnas de una fila suman más de 12, las que sobran bajan a la línea siguiente (útil a propósito, como verás en responsive).
  3. La grid usa Flexbox: por eso las columnas sin número se reparten solas el espacio libre.

3.4 Columnas responsive

Aquí está la magia: puedes indicar varios anchos para la misma columna, uno por breakpoint. Se aplica el del mayor breakpoint que se cumpla.

Cómo se lee col-12 col-md-6 col-lg-3: "en móvil ocupa 12 (todo el ancho); desde tablet (md) ocupa 6 (2 por fila); desde portátil (lg) ocupa 3 (4 por fila)".

Por qué funciona: 4 columnas de 6 suman 24 > 12, así que pasan a 2 filas automáticamente. row-cols-* hace lo mismo indicando cuántas columnas por fila en vez de su ancho: es perfecto para listados de tarjetas.

g-3 es el gutter (espacio entre columnas). Va de g-0 a g-5; gx-* solo horizontal y gy-* solo vertical.

  • offset-{bp}-{n} empuja la columna n posiciones. Alternativa moderna: ms-auto (margin-start auto) para mandarla a la derecha.
  • order-{bp}-{0..5}, order-first, order-last: muy útil en responsive, por ejemplo para que la imagen salga arriba en móvil y a la derecha en escritorio (order-first order-md-last).

Además de la rejilla, casi todas las utilidades de Bootstrap aceptan infijo de breakpoint con el patrón {propiedad}-{bp}-{valor}. Esto permite mostrar, ocultar, alinear o espaciar distinto según el dispositivo.

  • Mostrar/ocultar: se combina un valor base con otro a partir de un breakpoint. d-none d-lg-block = "oculto, y visible desde lg". d-lg-none = "visible hasta lg".
  • Flex responsive: flex-column flex-md-row apila en móvil y pone en línea en pantallas grandes. Es el patrón más usado para cabeceras, barras de herramientas o fichas.
  • Imágenes: siempre img-fluid para que nunca desborden su contenedor.
  • Vídeos/iframes: ratio ratio-16x9 (también 1x1, 4x3, 21x9) mantiene la proporción a cualquier ancho.
  • Mobile first: diseña primero para móvil (clases sin infijo) y añade cambios para pantallas mayores. Es más simple que al revés.
Cómo probar el responsive

En el navegador abre las herramientas de desarrollo (F12 o ⌥⌘I en Mac) y activa el modo dispositivo (Ctrl/⌘ + Shift + M). Puedes elegir modelos de móvil o arrastrar el ancho y ver cómo cambian los breakpoints.

5. Utilidades: el "CSS en clases"

Las utilidades son clases que aplican una sola propiedad CSS. Combinándolas puedes dar espacio, color, bordes o alinear sin escribir CSS. Es lo que más se usa en el día a día.

5.1 Espaciado: márgenes y padding

Nomenclatura: {propiedad}{lado}-{bp}-{tamaño}

ParteValores
Propiedadm = margin · p = padding
Ladot top · b bottom · s start (izq.) · e end (dcha.) · x izq.+dcha. · y arriba+abajo · (nada) los 4 lados
Tamaño0=0 · 1=.25rem · 2=.5rem · 3=1rem · 4=1.5rem · 5=3rem · auto (solo margin). Márgenes negativos: no por defecto.
Ejemplosmt-3 margin-top 1rem · px-4 padding lateral 1.5rem · mx-auto centrar un bloque con ancho · mb-md-0 sin margen inferior desde md
¿Por qué "start/end" y no "left/right"?

Para soportar idiomas que se escriben de derecha a izquierda (árabe, hebreo). En una página RTL, ms-3 se convierte automáticamente en margen derecho. En Bootstrap 4 eran ml-/mr-: si copias código antiguo, tenlo en cuenta.

  • Colores temáticos: primary, secondary, success, danger, warning, info, light, dark. Se usan como text-*, bg-*, border-*, btn-*, alert-*… Usar los nombres semánticos (y no "azul") permite cambiar la paleta entera desde un sitio.

8. Componentes más importantes

Los componentes son piezas de interfaz ya diseñadas. Algunos son solo CSS (botones, cards, alerts estáticas…) y otros necesitan el JavaScript de Bootstrap (modales, desplegables, tooltips…). Los he agrupado para que cada ejemplo muestre varios a la vez.

Dos formas de activar el JavaScript de un componente
  1. Con atributos data-bs-* (sin escribir código): <button data-bs-toggle="modal" data-bs-target="#miModal">. Es lo más cómodo.
  2. Con la API JavaScript: const m = new bootstrap.Modal('#miModal'); m.show();. Necesario cuando la acción depende de tu lógica (p. ej., abrir un modal tras validar un formulario).

9. Estilos propios: personalizar y sobrescribir Bootstrap

Hay cuatro niveles de personalización, de más sencillo a más potente. Elige el mínimo que resuelva tu necesidad.

9.1 Sobrescribir con CSS propio: la especificidad

Reglas para sobrescribir sin pelearte con Bootstrap
  1. Nunca edites bootstrap.min.css: perderías los cambios al actualizar.
  2. Carga tu CSS después; con la misma especificidad gana tu regla.
  3. Si no gana, sube la especificidad un poco (.mi-web .btn) en lugar de usar !important. Las utilidades de Bootstrap llevan !important a propósito, así que no intentes sobrescribirlas: cambia la clase.
  4. Mejor que modificar .btn-primary globalmente: crea tus propias variantes (.btn-marca) reutilizando las variables del componente.

9.2 Variables CSS: la forma moderna

En Bootstrap 5.3 casi todo se controla con variables CSS. Hay variables globales (--bs-primary, --bs-body-font-family, --bs-border-radius…) y variables de cada componente (--bs-btn-bg, --bs-card-border-color…). Cambiar una variable de componente es la forma más limpia de crear variantes.

10. Capítulo especial: formularios

Los formularios son probablemente la parte de Bootstrap con más valor práctico: unifican el aspecto de todos los controles en todos los navegadores, los hacen accesibles y responsive, y ofrecen un sistema de validación visual muy completo.

Las 5 clases que más vas a usar
  • .form-label → la etiqueta <label>.
  • .form-control → inputs de texto, email, password, number, date, file y textarea.
  • .form-select → los <select>.
  • .form-check + .form-check-input + .form-check-label → checkbox, radio y switch.
  • .form-text → texto de ayuda bajo un campo.

10.1 Controles básicos

Ejemplo 16 · Inputs, textarea, select, file, range, tamaños y estados

  • Etiqueta + campo: el for del label debe coincidir con el id del input. Así, al pulsar la etiqueta se enfoca el campo y los lectores de pantalla saben qué es.
  • aria-describedby une el campo con su texto de ayuda: el lector lo lee al entrar en el campo.

11. Validación de formularios y visualización de errores

Validar es comprobar que los datos son correctos antes de enviarlos, y sobre todo decírselo bien al usuario: qué campo falla, por qué y cómo arreglarlo. Bootstrap no valida nada por sí mismo: se apoya en la validación nativa de HTML5 (la Constraint Validation API del navegador) y pone la parte visual.

Importante

La validación en el navegador es para la experiencia de usuario, no para la seguridad: cualquiera puede saltársela. El servidor siempre debe volver a validar los datos.

11.1 Piezas del sistema de validación

PiezaQué hace

Las capas y para qué sirve cada una:

  1. Resumen de errores (alert) arriba del formulario: imprescindible en formularios largos, porque el error puede quedar fuera de la pantalla. Cada error es un enlace al campo. Al mostrarlo se le da el foco para que los lectores de pantalla lo anuncien.
  2. Color del borde + icono dentro del campo: identificación inmediata. El icono es importante porque no se debe transmitir información solo con color (daltonismo).
  3. Mensaje concreto bajo el campo (invalid-feedback): dice qué está mal y cómo corregirlo. "Campo incorrecto" no ayuda; "La letra no corresponde al número" sí.
  4. Tooltip: alternativa cuando no hay espacio debajo (formularios en línea, tablas editables).
  5. Mensaje de acierto (valid-feedback): úsalo con moderación, solo donde aporte (usuario disponible, contraseña segura, provincia detectada…).

Cómo cambiamos el icono: Bootstrap lo dibuja como background-image (un SVG) del input. Sobrescribimos esa propiedad con más especificidad (.iconos-x .form-control.is-invalid) y nuestro SVG con una cruz. Con Sass se haría cambiando la variable $form-feedback-icon-invalid. Los iconos de los mensajes usan los códigos de la fuente Bootstrap Icons.

11.4 Validación personalizada con funciones JavaScript

Cuando las reglas de HTML5 no bastan, escribimos funciones de validación propias y las integramos en el sistema de Bootstrap. La clave es separar tres responsabilidades:

1 Funciones puras

Reciben un valor y devuelven si es válido: validarDNI("12345678Z") → true. No tocan el HTML, así que se pueden reutilizar y probar en cualquier sitio (incluso en el servidor con Node).

2 Reglas por campo

Para cada campo, una función que devuelve el mensaje de error o una cadena vacía si está bien. Combina reglas nativas y funciones propias.

3 Pintar el resultado

Una única función marcar() que llama a setCustomValidity(), pone is-valid/is-invalid y escribe el mensaje. Así todo el formulario se ve igual.

¿Por qué usar setCustomValidity y no solo poner la clase is-invalid?

Porque así el navegador "sabe" que el campo es inválido: form.checkValidity() devolverá false, el selector :invalid funcionará (y con él .was-validated), y campo.validationMessage contendrá tu mensaje. Las reglas propias quedan integradas con las nativas en un único sistema.

¿Cuándo validar? (experiencia de usuario)
  • No mostrar errores mientras el usuario empieza a escribir un campo por primera vez: es molesto.
  • Validar al salir del campo (blur) la primera vez; a partir de ahí, en cada pulsación (input) para que vea cómo se corrige.
  • Al enviar, validar todo, mostrar el resumen y llevar el foco al primer error.
  • Validaciones costosas (consultar al servidor) con debounce: esperar a que el usuario deje de escribir ~500 ms.

    12. Templates (plantillas): uso y recomendaciones

    Un template es un sitio o una página ya maquetada con Bootstrap (HTML + CSS + JS + imágenes) que se usa como punto de partida: una landing page, un panel de administración, una tienda, un portfolio… En lugar de empezar desde cero, adaptas los contenidos y los estilos.

    Ventajas
    • Ahorro de tiempo enorme en maquetación.
    • Diseño profesional y probado en distintos dispositivos.
    • Aprendes viendo cómo están resueltos componentes complejos.
    • Ideal para prototipos y para presentar ideas a un cliente.
    Riesgos
    • Código innecesario (plugins, librerías, CSS que no usas) → web más lenta.
    • Versiones antiguas de Bootstrap (3 o 4) o de jQuery con fallos de seguridad.
    • Licencias: algunas exigen mantener el enlace al autor o no permiten uso comercial.
    • Tu web se parecerá a muchas otras si no la personalizas.

    12.1 Cómo trabajar con un template paso a paso

    1. Elegir bien: comprueba la versión de Bootstrap (mejor 5.3), la fecha de la última actualización, la demo en móvil y la licencia (MIT o similar si es para un proyecto real o comercial).
    2. Descargar y estudiar la estructura: localiza el index.html, las carpetas css/, js/, img/ o assets/, y si incluye las fuentes scss/.
    3. Identificar qué es Bootstrap y qué es del autor: el CSS propio del template suele estar en style.css o main.css. Ahí es donde harás tus cambios.
    4. Personalizar sin romper: cambia colores y fuentes mediante variables (CSS o Sass), no editando cientos de reglas. Si el template trae SCSS, compílalo con tus variables.
    5. Sustituir contenidos: textos, imágenes (optimizadas: WebP, tamaños adecuados, alt descriptivos) y enlaces.
    6. Limpiar: elimina secciones, plugins y librerías que no uses (animaciones, carruseles, mapas…).
    7. Revisar accesibilidad y rendimiento: Lighthouse (en las DevTools de Chrome) y el validador W3C.
    8. Respetar la licencia: mantén los créditos si la licencia lo exige.

    12.2 Ejemplos oficiales: el mejor punto de partida para aprender

    La propia documentación ofrece una colección de plantillas sencillas, gratuitas y con código limpio en getbootstrap.com/docs/5.3/examples: Album (galería), Pricing (precios), Checkout (formulario de compra con validación), Product, Blog, Dashboard (panel de administración), Sign-in (login), Sticky footer, Carousel, Headers, Footers, Sidebars, Features, Heroes… Son ideales para clase porque no añaden librerías extra.

    Recomendaciones
    • Para aprender: empieza con los ejemplos oficiales; los templates comerciales son demasiado complejos.
    • Para proyectos: un template bien elegido + personalización con variables es más productivo que maquetar todo a mano.
    • Para paneles de administración: AdminLTE, CoreUI o Tabler ya resuelven menús laterales, tablas y gráficos.
    • Desconfía de templates "gratuitos" de webs desconocidas: pueden incluir scripts maliciosos o enlaces ocultos. Descarga siempre de fuentes reconocidas.
